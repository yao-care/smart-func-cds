# 事件回應計畫與演練記錄（ISO 27001 A.5.24）

> ⚠️ 本檔含「程序（常設）」與「演練記錄（每次填寫）」兩部分。程序部分維護為最新；
> 演練記錄每次桌面／實機演練後新增一筆，**填入真實資訊**。
> 目前 smart-func-cds **尚無演練記錄**，第 5 節為待填。

## 1. 範圍與目標

- 對象系統：smart-func-cds（GitHub Pages 靜態 SMART-on-FHIR CDS，自訂網域
  `smart-func-cds.yao.care`）。
- 目標：在偵測到資安事件後，能於 RTO 內遏制、復原並對外溝通。

## 2. 事件分級

| 等級 | 定義 | 範例 | 目標回應時間 |
|---|---|---|---|
| P1 嚴重 | 影響臨床／受測者安全或大量資料 | Pages 被植入惡意腳本、供應鏈 RCE 在用路徑、密鑰外洩可改部署 | 立即（≤1 小時內遏制） |
| P2 高 | 服務中斷或潛在資料風險 | 部署中斷、相依套件 High CVE 在用路徑、DNS 異常 | ≤4 小時 |
| P3 中／低 | 有限影響、可排程修補 | 非在用路徑的相依 CVE、低風險 SAST 告警 | ≤5 個工作天 |

## 3. 回應流程

```mermaid

  E --> F[驗證]
  F --> G[事後檢討與記錄]
```

### 各情境的遏制手段

- **Pages 竄改／惡意部署**：回滾 GitHub Pages 部署（`git revert` + 重新觸發
  `deploy.yml`），必要時暫停 Pages。
- **供應鏈污染**：以 `pnpm.overrides` 釘住安全版本或移除受影響套件，重建並重新部署。
  Actions 端則比對 `uses:` 的 commit SHA 是否被變更（本 repo 一律釘 40 字元 SHA）。
- **密鑰外洩**：撤銷並輪替 GitHub Actions secrets、部署 token、
  `PUBLIC_CONTRIBUTION_WORKER_URL` 對應 worker 的憑證。
- **DNS／網域劫持**：聯絡網域註冊商與 DNS 服務商，鎖定並還原紀錄。
- **收案端異常**：本系統不持有上傳後的資料；若懷疑 GCM 收案端受影響，
  依 [聯絡窗口](incident-response-contacts.md) 通報該機構，並評估是否暫時停用
  結果頁的上傳入口。

## 4. 對外溝通

- 內部通報：依 [事件回應聯絡窗口](incident-response-contacts.md)。
- 對收案機構：涉及已上傳 FHIR 資料風險時，依資料處理協議通知對應窗口。
